# 용어집 (Glossary)

팀이 공유하는 **유비쿼터스 언어**. 코드 식별자·문서·대화에서 같은 단어를 같은 뜻으로 쓴다.

- **시스템 공통 용어**(아키텍처·운영)는 이 문서에 둔다.
- **도메인 고유 용어**는 본래 그 도메인 안(`{도메인}/docs/glossary.md`)에 두는 것이 원칙이나,
  아직 도메인별 문서가 없어 현재는 아래 도메인 섹션에 모아 둔다. 신규 시스템이 생기면 분리한다.
- 새 용어를 도입하면 PR에서 이 문서를 갱신한다.

---

## 아키텍처 공통

## 바운디드 컨텍스트 (Bounded Context)
하나의 모델·언어가 일관되게 적용되는 경계. 이 레포에서는 최상위 시스템 1개(`url-shortener/`,
`notification-system/`)가 하나의 컨텍스트다. 컨텍스트 간 모델을 공유하지 않는다.

## 애그리거트 / 애그리거트 루트 (Aggregate / Aggregate Root)
함께 변경되며 일관성을 함께 지켜야 하는 객체 묶음과, 그 유일한 진입점. 불변식은 루트가 책임진다.

## 엔티티 / 값 객체 (Entity / Value Object, VO)
엔티티는 식별자로 구분되는 객체, VO는 식별자 없이 값으로 동등성을 판단하는 불변 객체.

## 포트 / 어댑터 (Port / Adapter)
포트는 애플리케이션이 소유한 인터페이스(진입점=인바운드, 출구=아웃바운드), 어댑터는 그 포트의
구현(웹·DB·외부연동). 의존성은 항상 어댑터 → 애플리케이션 → 도메인 방향.

## 유스케이스 (Use Case)
외부가 도메인을 호출하는 인바운드 포트 하나가 표현하는 응용 동작(예: "단축 URL 생성").

## 도메인 서비스 vs 애플리케이션 서비스
도메인 서비스는 한 엔티티에 담기 애매한 **순수 도메인 로직**, 애플리케이션 서비스는 트랜잭션·
포트 호출·오케스트레이션 담당(비즈니스 규칙 자체는 도메인에 위임).

## 도메인 이벤트 (Domain Event)
"무슨 일이 일어났다"는 과거형 사실(예: `NotificationSent`). 도메인에서 정의하고 애플리케이션
서비스에서 발행한다.

## 운영 · 신뢰성 공통

## 멱등성 (Idempotency)
같은 요청을 여러 번 처리해도 결과가 한 번 처리한 것과 같은 성질. 멱등키(`dedupKey`,
`Idempotency-Key`)로 중복 요청을 한 번만 반영한다.

## 최소 한 번 (at-least-once)
접수된 작업이 최소 한 번은 시도되도록 보장하는 전달 보장 수준. 중복이 생길 수 있어 멱등성과 짝.

## 팬아웃 (fan-out)
한 건의 입력이 다수의 처리·쓰기로 퍼지는 것(예: 캠페인 1건 → 수백만 발송, 디바이스 수만큼 증폭).

## 스로틀링 (Throttling)
같은 대상에게 과도하게 보내지 않도록 발송 속도/빈도를 제한하는 것(사용자 피로도 제어).

## 적체 해소 시간 (Backlog Drain Time)
쌓인 작업이 provider 쿼터 한도 안에서 모두 빠지는 데 걸리는 시간. 발송 속도가 아니라 이 값으로
용량을 산정한다.

## URL 단축 도메인

## 단축 키 (Short Key)
원본 URL을 가리키는 짧고 유일한 식별자. Base62 7자리 채택.

## Base62
`a–z A–Z 0–9` 62문자로 수를 표현하는 인코딩. 짧고 URL-safe한 키 생성에 쓴다.

## 원본 URL (Long URL)
단축 대상이 되는 원래의 긴 URL. 단축 키로 접근 시 이곳으로 리다이렉트한다.

## 커스텀 별칭 (Custom Alias)
사용자가 직접 지정하는 단축 키(선택 기능).

## 리다이렉트 (Redirect)
단축 키 접근을 원본 URL로 보내는 응답(`301`/`302`).

## 알림 도메인

## 채널 (Channel)
알림 전달 경로: 모바일 푸시(APNs/FCM), SMS, 이메일.

## 프로바이더 (Provider)
실제 발송을 수행하는 서드파티(APNs, FCM, SMS 게이트웨이 등). 최종 사용자 도달은 provider에 달려
있어 시스템의 보장 범위 밖.

## 디바이스 토큰 (Device Token)
푸시 발송 대상을 식별하는 단말 토큰. 등록/갱신 대상.

## 수신 거부 (opt-out)
사용자가 채널/카테고리별로 알림을 받지 않도록 설정하는 것.

## 카테고리 (Category)
알림 성격 구분: `transactional`(주문/OTP 등)·`marketing`. 동의·스로틀 판정 근거.

## 아웃박스 (Outbox)
발송 사실을 DB에 먼저 기록해 메시지 유실 없이 비동기 발송하는 패턴의 기록 테이블.

## 전달 (Delivery)
한 알림 요청이 개별 디바이스/채널로 실제 발송되는 단위. 요청 1건이 디바이스 수만큼 delivery로 증폭.

## dedupKey
producer가 부여하는 멱등키. `(producerId, dedupKey)`로 중복 발송을 막는다.
